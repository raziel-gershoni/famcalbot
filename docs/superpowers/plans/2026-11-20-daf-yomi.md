# Daf Yomi (release 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Daf Yomi" switch in Settings (Jewish calendar only) that adds one quiet line, "Daf Yomi · Arachin 3", under the day header of the Month's picked-day list and under each Agenda day header.

**Architecture:** The day's page is worked out in the browser from the day key by `@hebcal/learning`'s `dafYomiBase` subpath (which needs only `@hebcal/hdate`, already in the home), through one function, `dafYomiOf`. The tractate's name comes from FamCal's own he/en/ru table in `messages/*.json`, keyed by hebcal's English name. The setting is a new `User.dafYomi` column, saved by the existing settings route, and reaches the home as one `dafYomi` prop that is true only when the setting is on and the culture is Jewish.

**Tech Stack:** Next.js 16, React 19, next-intl, Prisma 7, `@hebcal/hdate` 0.23.1, `@hebcal/learning` 6.13.1 (new, pinned exactly), lucide-react, tsx smokes.

**Spec:** `docs/superpowers/specs/2026-11-19-responsive-home-design.md` §6 (release 1), §8 (copy), and the Status line (the owner's approval of the wording, 2026-11-20).

## Global Constraints

- `@hebcal/learning` pinned to exactly `6.13.1` (no caret). The browser imports only `@hebcal/learning/dafYomiBase`, never the package's main entry (it imports `@hebcal/core`, which is kept out of the browser). One copy each of `@hebcal/core` and `@hebcal/hdate` after the install (`npm ls`).
- Size: at most about 15 KB gzipped added to the home's chunk. Measure it (Task 1, Step 7). Over budget, stop and report: the spec's fallback (the range answer carries the daf) is a change of design, not a silent swap.
- One function from a day to its daf (`dafYomiOf`), used by every place that shows it.
- Tractate names come from FamCal's own table only (`calendarHome.dafYomi.tractates`), never from hebcal's translation files or `DafPage.render`.
- The line is "Daf Yomi · <tractate> <page>": the page in gematriya in Hebrew ("ג׳", "ט״ו"), digits in English and Russian. "דף" is never said twice.
- The line shows under the picked day's header (MonthPicked) and under each Agenda day header, never on a fold line ("Nothing planned Sat 17 – Sun 18"), never anywhere else (no month squares, summaries, voice, bot, Google copy).
- Muted, like the holiday line; a lucide `BookOpen` icon, `aria-hidden`; nothing under 11 px; logical properties only; no hover; Hebrew RTL correct.
- The switch is shown only while the calendar picked in the form is Jewish. Picking General hides it and keeps the stored value; the value is never reset by a culture change (`defaultsForCulture` does not touch it).
- Settings and home copy is i18n in `messages/{en,he,ru}.json`; Hebrew gender-neutral, Russian formal and natural; exact wording below (approved 2026-11-20).
- Day keys are calendar days: no `Date` local getter or setter in new code (CLAUDE.md wall-time rule); build the Hebrew date only with `hebrewDateOf` (`src/lib/calendar-view/hebrew-date.ts`).
- Never run `npm run build` (it migrates prod). The migration is hand-written and applies on deploy. `npx prisma generate` is fine.
- Smokes run with the fake env only (`bash scripts/ci-smokes.sh`, or one file: the same env as `scripts/ci-smokes.sh` builds).

## Review Focus

1. **A day before the first cycle** (the Month reaches back to January 1900; Daf Yomi began 11 September 1923): no line and no error, never hebcal's `RangeError` reaching React. Pinned in Task 1 (`dafYomiOf('1923-09-10') === null`) and Task 3 (the line renders nothing for it).
2. **A device in another zone than Israel** (west of Greenwich, or UTC+14): the same day key gives the same page. Pinned in Task 1 (the smoke re-runs itself under UTC, Pacific/Kiritimati and America/Los_Angeles).
3. **A culture switch with the setting on**: picking General hides the switch and keeps `dafYomi` stored, the home shows no line; picking Jewish again brings both back as they were. Pinned in Task 2 (S15) and Task 3 (page-data's gate).
4. **The browser bundle**: an import of `@hebcal/learning` (the main entry) instead of the subpath would pull `@hebcal/core` into the home. Pinned in Task 1 (module graph) and Task 3 (the render smokes' client-safety checks).
5. **A second copy of `@hebcal/hdate`** from the install would register hebcal's Hebrew and Russian on a different `Locale`, and the home's Hebrew month names would change. Pinned in Task 1 (one resolved copy).

  - `export function dafYomiOf(day: DayKey): DafOfDay | null` — null for a key that is no real day or is before `DAF_YOMI_FIRST_DAY` (checked before hebcal is asked, so its `RangeError` never happens); otherwise `new DafYomi(hebrewDateOf(day))` from `@hebcal/learning/dafYomiBase`, read through `getName()` and `getBlatt()`.

  - `export function dafYomiWords(day: DayKey, lang: string, tractates: Readonly<Record<string, string>>): { tractate: string; page: string } | null` — the line's two arguments: the table's name for the day's tractate (the English key itself when the table lacks it: the smoke makes that impossible, and a line is never hidden for it) and `dafPageText`. null when `dafYomiOf` is null.
- Produces (messages): `calendarHome.dafYomi.line` with arguments `{tractate}` and `{page}`, and `calendarHome.dafYomi.tractates` (an object, read whole with `t.raw`).
