# F1: the shared design layer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (lean: one Sonnet implementer for all four tasks in one worktree, one Opus whole-branch review, one fix round). Commit per task.

**Goal:** lift the home's design layer into `components/app-ui/` so every later screen (W1, W3, A) is built on it. The home looks exactly the same afterwards.

**Architecture:**
- Three root classes replace the one root, `.ch-home`:
  - `.ch-app` carries the tokens, base type and shared parts (the theme scope);
  - `.ch-screen` carries a full screen's frame (height, safe areas, page-root paint);
  - `.ch-home` stays on the home's root as its own marker.
- Each class keeps today's specificity, because one class replaces one class. Every `--ch-*` and `ch-*` name is kept.
- `AppScreen` is the screen root and the single owner of Telegram's BackButton. `AppScope` is the zero-height theme scope that Settings' time picker uses today.

**Tech stack:** Next.js 16, React 19, next-intl, inline `<style>` CSS strings, tsx smoke scripts.

**Spec:** `docs/superpowers/specs/2026-10-19-screens-and-colours-design.md` §4. The research map with file:line is in the session's scratchpad (`f1-research.md`).

## Global constraints

- **No visual change on the home, the editor or Settings' time picker.**
  - Proof 1, in the repo: a token golden.
  - Proof 2, scratch: identical screenshots from the parent commit and the branch.
  - Visual changes happen only where this plan names them (T4's cards and the dashboard loader).
- **Names and roots.**
  - Every `--ch-*` and `ch-*` name is kept.
  - A root selector `.ch-home…` becomes `.ch-app…` (theme) or `.ch-screen…` (frame), never a compound like `.ch-app.ch-home`.
- **CSS rules.**
  - Text is at least 11 px; tap targets are at least 44 px.
  - Logical properties only.
  - No `:hover`.
  - No `overflow: hidden` in new CSS.
  - No hex outside token blocks in new CSS.
- **Code rules.**
  - `components/app-ui/*` is client-safe: no server-only imports (render #21 walks the module graph).
  - Each screen has one BackButton owner: AppScreen's `onBack`. No other component calls `useTelegramBackButton`.
- **Strings.**
  - Every new string goes in `messages/{en,he,ru}.json`, natural copy: gender-neutral Hebrew, formal вы in Russian.
  - `scripts/check-i18n-parity.ts` passes.
  - Keys land with their first use; there are no unused keys.
- **Gate.**
  - Run `npx prisma generate && npx tsc --noEmit && npx eslint . && bash scripts/ci-smokes.sh`.
  - Never run `npm run build`.
  - Grep with `--exclude='.env*'`.

## Owner choice in this plan (recommended default)

The spec's §4 also lists ScreenHeader, day chips, notice, badge, meter and empty states, plus the `ui` keys Back, Close, Save and Saved. No screen uses any of them until W1. **Default:** build each in W1 beside the first screen that uses it (Settings, Subscription), so it is drawn and tested against real content, not in isolation. F1 then stays a pure lift plus the cards that already have users.
